    after the last existing line (the meeting_history update policy). Add a blank line first,
    then the block exactly as written:

    ```sql
    -- ---------------------------------------------------------------------------
    -- pipeline_jobs: background pipeline execution tracking (Phase 2+)
    -- ---------------------------------------------------------------------------

    create table if not exists public.pipeline_jobs (
      job_id uuid primary key default gen_random_uuid(),
      user_id uuid not null,
      session_id text not null,
      status text not null default 'pending',
      stage text,
      created_at timestamptz default now(),
      completed_at timestamptz,
      error text
    );

    -- NOTE: Run this entire block in the Supabase SQL Editor before starting Phase 2.
    -- Status values: 'pending' | 'running' | 'completed' | 'failed'
    -- Stage holds the current named pipeline stage (e.g. 'fact_extraction', 'drafting').

    create index if not exists pipeline_jobs_session_created_idx
      on public.pipeline_jobs (session_id, created_at desc);

    alter table public.pipeline_jobs enable row level security;

    drop policy if exists "Users can read their own pipeline jobs" on public.pipeline_jobs;
    create policy "Users can read their own pipeline jobs"
      on public.pipeline_jobs
      for select
      using (auth.uid() = user_id);

    drop policy if exists "Users can insert their own pipeline jobs" on public.pipeline_jobs;
    create policy "Users can insert their own pipeline jobs"
      on public.pipeline_jobs
      for insert
      with check (auth.uid() = user_id);

    drop policy if exists "Users can update their own pipeline jobs" on public.pipeline_jobs;
    create policy "Users can update their own pipeline jobs"
      on public.pipeline_jobs
      for update
      using (auth.uid() = user_id)
      with check (auth.uid() = user_id);
    ```

    Design notes (do not deviate):
    - user_id is required (not null) so RLS policies can scope by auth.uid().
    - status has a default of 'pending' matching the four-state lifecycle used by Phase 2.
    - stage is nullable — it is null until the pipeline sets it on first update.
    - error is nullable — only populated on 'failed' status.
    - completed_at is nullable — only set when status transitions to 'completed' or 'failed'.
    - The index covers the expected query pattern: fetch all jobs for a session, newest first.
    - Three RLS policies mirror the meeting_history pattern exactly (select, insert, update).
    - Use `drop policy if exists` before each `create policy` to make the block idempotent
      (safe to re-run in the SQL editor).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase RLS → pipeline_jobs | User A must not read or write User B's pipeline jobs |
| TypeScript interface → UI rendering | New optional fields must not break existing card rendering that doesn't check for them |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | pipeline_jobs RLS | mitigate | RLS policies use `auth.uid() = user_id` for all three operations (select, insert, update). No service-role bypass in application code — only Supabase anon/user key is used by the app. |
| T-03-02 | Information Disclosure | pipeline_jobs.error column | accept | Error messages may contain internal stage names but no user PII. Phase 2 will sanitize before exposing to UI. |
| T-03-03 | Tampering | TypeScript optional fields | accept | Optional fields with no default means undefined at runtime — UI components must use optional chaining (item.confidence ?? "low") which Phase 3 will enforce. No security impact in Phase 1 since fields are not yet rendered. |
| T-03-04 | Denial of Service | pipeline_jobs table growth | accept | One row per job per session. Jobs are short-lived background tasks. Retention policy (cleanup of old jobs) is a Phase 4 concern. |
</threat_model>
