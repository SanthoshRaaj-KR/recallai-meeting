# Plan 03-01: SummarizerAgent

## Goal

A `SummarizerAgent` class exists that accepts a raw meeting transcript string plus meeting metadata, calls the OpenAI Agents SDK with a structured output schema matching `MeetingRecord`, and returns a fully populated `MeetingRecord` with participant-attributed action items and correct `status` tagging.

## Context

Phase 2 produced the canonical `MeetingRecord` and `ActionItem` Pydantic models in `storage/models.py`. These are the data contracts this agent must satisfy — do not redefine them.

`jarvis.py` accumulates transcripts via `MeetingState.get_transcript()` which returns lines in the format:

```
Alice: We should ship the API by Friday.
Bob: I'll write the RFC today.
Alice: And I'll do code review by Thursday.
```

Each line is `"{participant_name}: {utterance}"`. This format is what the agent will receive.

The project uses `openai-agents==0.4.2` (the `openai-agents` package, not raw `openai`). Refer to the SDK's `Agent`, `Runner`, and response_format / output_type patterns. The agent must use structured output so the response is a typed Pydantic object, not free text that needs regex parsing.

## TDD Approach

This plan follows Red-Green-Commit:

1. Write failing tests first in `tests/test_summarizer.py`
2. Implement `agents/summarizer.py` to make tests pass

### Task 2: Implement SummarizerAgent

**Prompt:**

Create `agents/__init__.py` (empty) and `agents/summarizer.py`.

The `SummarizerAgent` class must satisfy every test from Task 1. Here is the exact contract:

**Class signature:**
```python
class SummarizerAgent:
    def __init__(self, model: str = "gpt-4o-mini"):
        ...

    async def run(
        self,
        transcript: str,
        meeting_meta: dict,
    ) -> MeetingRecord:
        ...
```

**Implementation requirements:**

1. **Import only from project modules and allowed SDK:** Use `from storage.models import MeetingRecord, ActionItem`. Use `from agents import Agent, Runner` from the `openai-agents` SDK. Do NOT import from `openai` directly for the agent logic.

2. **Structured output schema:** Define a `SummaryOutput` Pydantic model that the agent uses as its `output_type`. This model captures the LLM's structured response before it is converted to a `MeetingRecord`. It should have fields:
   ```python
   class SummaryOutput(BaseModel):
       summary_text: str
       topics_covered: list[str]
       decisions: list[str]
       action_items: list[ActionItem]  # from storage.models
       participants: list[str]
   ```
   Use `Agent(output_type=SummaryOutput, ...)` so the SDK enforces structured JSON output.

3. **System prompt for the agent** — embed this verbatim as the agent's `instructions`:
   ```
   You are a meeting summarizer. Given a meeting transcript where each line is
   "{speaker}: {utterance}", extract the following as structured JSON:

   - summary_text: A 2-4 sentence prose summary of what was discussed and decided.
   - topics_covered: A list of distinct topics discussed (short phrases, e.g. "API contract", "changelog update").
   - decisions: A list of decisions the group reached (complete sentences).
   - action_items: A list of tasks where each item has:
       - owner: The FULL NAME of the participant who committed to the task.
         Use the last speaker who explicitly accepted or volunteered for it.
         If ownership is genuinely ambiguous, use the last speaker who mentioned it.
         NEVER leave owner blank. NEVER use "TBD", "Unknown", or "Someone".
       - task: A clear description of what must be done.
       - due: Optional due date string if mentioned, otherwise omit.
   - participants: The list of unique speaker names who appeared in the transcript.

   Accuracy rules:
   - Only include decisions that were explicitly agreed upon, not just proposed.
   - Only include action items where someone explicitly accepted ownership.
   - Extract participant names exactly as they appear in the transcript.
   ```

4. **Runner call:** Use `await Runner.run(agent, input=prompt)` where `prompt` is a string that contains the transcript text. The result's `.final_output` will be the `SummaryOutput` Pydantic object.

5. **Post-processing after the LLM call:**
   - Validate that no `ActionItem` has a blank `owner`. If any do, raise `ValueError(f"ActionItem owner must not be blank: {item.task!r}")`.
   - Set `raw_transcript_chars = len(transcript)`.
   - Set `summarized_at = int(time.time())`.
   - If `len(transcript) < 500`, set `status = "partial"`. Otherwise set `status = "complete"`.
   - Assemble and return a `MeetingRecord` using `meeting_meta` dict fields plus the extracted `SummaryOutput` fields. Set `end_ts` from `meeting_meta.get("end_ts")`, `duration_seconds` from `meeting_meta.get("duration_seconds")`.

6. **Error propagation:** Do not catch exceptions from the SDK runner. Let them bubble up. The caller (jarvis.py wiring in Plan 03-02) is responsible for error handling.
