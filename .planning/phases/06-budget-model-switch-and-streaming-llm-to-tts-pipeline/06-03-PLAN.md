<objective>
Wire the streaming TTS pipeline into both LLM response paths in jarvis.py:

1. **Direct query path** (handle_query tool-calling loop): On the final answer round (finish_reason != "tool_calls"), use OpenAI streaming (`stream=True`) to receive tokens incrementally. Accumulate tokens at sentence boundaries and call speak() via asyncio.to_thread as each sentence completes — so the user hears the first sentence before the full LLM response has finished generating.

2. **Memory query path** (handle_query → _handle_memory_query → OrchestratorAgent): The OrchestratorAgent returns a full answer string (structured output via openai-agents SDK makes true streaming complex). Replace `asyncio.to_thread(speak, result.answer, bot_id)` with `await speak_chunked(result.answer, bot_id)` — so the first sentence is TTS'd and played while subsequent sentences are still being processed.

Purpose: Minimize the silence gap between the user asking a question and hearing the first word. For long answers, this cuts perceived latency from (full_generation + full_tts) to (first_sentence_generation + first_sentence_tts).
Output: _stream_llm_and_speak() helper + updated call sites in handle_query() and the memory query path.
</objective>

**Step 1: Add _stream_llm_and_speak() to jarvis.py**

Insert this coroutine AFTER speak_chunked() (added in plan 06-02) and BEFORE the TOOLS section. This is a synchronous-client streaming approach using asyncio.to_thread for the stream iteration:

```python
async def _stream_llm_and_speak(messages: list, bot_id: str) -> None:
    """Stream the final LLM answer and speak each sentence as it completes.

    Uses client.chat.completions.create(stream=True) to receive tokens
    incrementally. Accumulates tokens and calls speak() via asyncio.to_thread
    each time a sentence-ending character (.!?) is followed by whitespace or
    the stream ends.

    This minimises the silence gap: the first sentence is spoken as soon as
    it is generated, before the rest of the answer exists.

    Args:
        messages: Chat message list for the completion call (same format as
                  the tool-calling loop in handle_query).
        bot_id: Recall.ai bot ID for audio output.
    """
    buffer = ""
    try:
        # Run the blocking stream iterator in a thread to avoid blocking the event loop.
        # We collect all chunks first via asyncio.to_thread, then process them.
        # This is simpler than a true async stream and avoids asyncio/thread boundary issues.
        def _run_stream() -> list[str]:
            """Collect streamed content tokens synchronously."""
            tokens: list[str] = []
            stream = client.chat.completions.create(
                model=OPENAI_MODEL,
                messages=messages,
                stream=True,
                max_tokens=300,
            )
            for chunk in stream:
                delta_content = chunk.choices[0].delta.content
                if delta_content:
                    tokens.append(delta_content)
            return tokens

        tokens = await asyncio.to_thread(_run_stream)

        # Process tokens, speaking each complete sentence as we go.
        # This preserves latency benefit: speak() starts when first sentence is complete.
        for token in tokens:
            buffer += token
            # Check if buffer now contains at least one complete sentence.
            # Look for sentence-ending punctuation followed by whitespace.
            while True:
                match = re.search(r'[.!?]\s', buffer)
                if match:
                    sentence = buffer[:match.start() + 1].strip()
                    buffer = buffer[match.end():].strip()
                    if sentence:
                        await asyncio.to_thread(speak, sentence, bot_id)
                else:
                    break

        # Speak any remaining text in the buffer after stream ends.
        remainder = buffer.strip()
        if remainder:
            await asyncio.to_thread(speak, remainder, bot_id)

    except Exception as e:
        logger.error("_stream_llm_and_speak error: %s", e)
        # If streaming fails, fall through (caller handles silence gracefully)
        raise
```
