# Plan 07-03: Wire New Pipeline into jarvis.py

**Phase:** 7 — Fully Agentic Meeting Pipeline Redesign
**Goal:** Wire the sentence buffer, dual-threshold flush, interrupt flush on wake word, rolling `.md` writing, History Manager routing, and end-of-meeting Pinecone upsert into `jarvis.py` — making the full real-time pipeline operational end-to-end.
**Depends on:** Plan 07-01 (rolling summarizer + meeting writer), Plan 07-02 (history manager agent)

---

## Context

All new agent classes exist after Plans 07-01 and 07-02. This plan modifies `jarvis.py` exclusively to wire them together. Changes are confined to five sections of `jarvis.py`:

1. **Module-level singletons** (after line 127): instantiate `MeetingWriterAgent`, `RollingSummarizerAgent`, `HistoryManagerAgent`.
2. **`websocket_endpoint`** (line 566): add sentence buffer state, flush logic on each transcript event, and interrupt flush in the wake-word branch.
3. **`handle_query`** (line 459): route `memory_query` through `HistoryManagerAgent` instead of (or before) `OrchestratorAgent`.
4. **`WebSocketDisconnect` handler** (line 617): trigger end-of-meeting Pinecone upsert alongside (not instead of) the existing `run_ingestion_pipeline` task.
5. **New helper `_flush_sentence_buffer`**: async function extracted to keep `websocket_endpoint` readable.

No other files are modified. All decisions referenced below are from `07-CONTEXT.md`.

### Task 2: Implement `_flush_sentence_buffer()` and integrate into `websocket_endpoint`

**File:** `jarvis.py`
**Action:** Modify — add `_flush_sentence_buffer` helper, modify `websocket_endpoint`
**Details:**

**New async helper `_flush_sentence_buffer(bot_id: str, force: bool = False) -> None`** (add before `websocket_endpoint`):
- Purpose: atomically drain the sentence buffer, summarize, write to `.md`, update index.
- Algorithm:
  ```python
  async def _flush_sentence_buffer(bot_id: str, force: bool = False) -> None:
      global _sentence_buffer, _last_flush_ts, _current_batch_num, _current_meeting_entry, _meeting_header_written

      async with _sentence_buffer_lock:
          now = time.time()
          sentence_count = len(_split_sentences("\n".join(_sentence_buffer)))
          time_elapsed = now - _last_flush_ts if _last_flush_ts > 0 else 0

          should_flush = force or (
              sentence_count >= SENTENCE_FLUSH_COUNT or
              (time_elapsed >= SENTENCE_FLUSH_SECONDS and sentence_count > 0)
          )

          if not should_flush or not _sentence_buffer:
              return

          batch_lines = list(_sentence_buffer)
          _sentence_buffer.clear()
          _last_flush_ts = now
          _current_batch_num += 1
          batch_num = _current_batch_num

      # Outside lock: LLM call + file I/O (non-blocking, but no lock held)
      batch_transcript = "\n".join(batch_lines)
      try:
          batch_summary = await rolling_summarizer.run(batch_transcript)
      except Exception as e:
          logger.error("RollingSummarizerAgent error: %s", e)
          return

      if _current_meeting_entry is None:
          logger.warning("_flush_sentence_buffer: no meeting entry, skipping write")
          return

      timestamp_str = datetime.datetime.now().strftime("%-I:%M %p")  # e.g. "10:32 AM"

      # Write header on first batch of a meeting
      if not _meeting_header_written:
          await meeting_writer.write_meeting_header(_current_meeting_entry)
          _meeting_header_written = True

      await meeting_writer.append_batch(
          entry=_current_meeting_entry,
          batch_num=batch_num,
          batch_summary=batch_summary,
          timestamp_str=timestamp_str,
      )

      # Update participants in index entry and upsert
      _current_meeting_entry.participants = list(
          set(_current_meeting_entry.participants) | set(batch_summary.speakers)
      )
      _current_meeting_entry.overview = batch_summary.summary_text  # latest batch as overview
      await meeting_writer.upsert_index(_current_meeting_entry)
      logger.info("Flushed batch %d (%d lines) to .md", batch_num, len(batch_lines))
  ```
  Note: `_split_sentences` is already defined in `jarvis.py` (Phase 6). Call it directly.
  Note: On macOS, `%-I` may not work — use `%I:%M %p` and strip leading zero manually if needed, or use `%I:%M %p`.

### Task 3: Route `memory_query` through `HistoryManagerAgent` in `handle_query()` and update disconnect handler

**File:** `jarvis.py`
**Action:** Modify — `handle_query` and `WebSocketDisconnect` handler
**Details:**

**`handle_query()` modification** (line 459):
- Replace the `if orchestrator is not None and _is_memory_query(query):` block (lines 464–483) with:
  ```python
  # Route memory queries: prefer HistoryManagerAgent (.md path) over OrchestratorAgent (Pinecone path)
  if _is_memory_query(query):
      routed = False
      if history_manager is not None:
          try:
              result = await history_manager.run(
                  query=query,
                  user_id="voice",
                  channel_id=SLACK_CHANNEL_ID,
              )
              routed = True
          except Exception as e:
              logger.error("HistoryManagerAgent error, falling back to OrchestratorAgent: %s", e)

      if not routed and orchestrator is not None:
          try:
              result = await orchestrator.run(query=query, user_id="voice", channel_id=SLACK_CHANNEL_ID)
              routed = True
          except Exception as e:
              logger.error("OrchestratorAgent error in handle_query: %s", e)

      if routed:
          if not result.needs_disambiguation:
              await _stream_llm_and_speak(result.answer, bot_id)
              return
          spoken = "Multiple meetings found. " + " ".join(
              f"Option {opt['index']}: {opt['title']} from {opt['date']}."
              for opt in result.disambiguation_options
          )
          await _stream_llm_and_speak(spoken, bot_id)
          return
  ```
  Note: Use `_stream_llm_and_speak` (Phase 6) instead of `asyncio.to_thread(speak, ...)` for consistency with Phase 6's streaming-first voice output.

**`WebSocketDisconnect` handler modification** (line 616):
- After the existing `asyncio.create_task(run_ingestion_pipeline(...))` call, add:
  ```python
  # D-10: Final buffer flush to .md on disconnect (belt-and-suspenders with Pinecone upsert)
  if _current_meeting_entry is not None:
      asyncio.create_task(_flush_sentence_buffer(bot_id, force=True))
  ```
  Both tasks fire-and-forget — the existing Pinecone path is preserved (D-10). Reset buffer state after disconnect so next meeting starts clean:

## Success Criteria

1. `SENTENCE_FLUSH_COUNT` and `SENTENCE_FLUSH_SECONDS` are configurable via env vars (defaults: 10 sentences, 120 seconds).
2. Each `transcript.data` WebSocket event appends to `_sentence_buffer` under `_sentence_buffer_lock`.
3. `_flush_sentence_buffer(force=False)` flushes when sentence count >= `SENTENCE_FLUSH_COUNT` OR time since last flush >= `SENTENCE_FLUSH_SECONDS` (whichever first — D-01).
4. Wake-word detection (both "full query" and "bare wake word" branches) awaits `_flush_sentence_buffer(force=True)` before dispatching `handle_query` — buffer is zero after wake word (D-02).
5. The meeting `.md` file at `meetings/{channel_id}/{date}_{meeting_id}.md` is created on first batch with a full header (D-05) and each subsequent batch appends a new `## HH:MM AM/PM — Batch N` section (D-03, D-04, D-06).
6. `meeting_index.json` is updated (upserted) after each batch flush.
7. `memory_query` in `handle_query` is routed to `HistoryManagerAgent` first; falls back to `OrchestratorAgent` on exception.
8. On `WebSocketDisconnect`, both the existing `run_ingestion_pipeline` task (Pinecone — D-10) AND a final `_flush_sentence_buffer(force=True)` task are created.
9. Buffer state (`_sentence_buffer`, `_current_meeting_entry`, `_current_batch_num`, `_last_flush_ts`, `_meeting_header_written`) is fully reset on disconnect so the next meeting starts clean.
10. `pytest tests/test_jarvis_rolling_pipeline.py -v` passes with 7 tests, no failures.
11. All existing tests (`pytest tests/ -v`) continue to pass — no regressions.
