# Plan 07-02: History Manager Agent

**Phase:** 7 — Fully Agentic Meeting Pipeline Redesign
**Goal:** Create a `HistoryManagerAgent` that reads the JSON meeting index, uses an LLM call to select the best matching meeting for a user's question, handles ambiguous matches via a disambiguation flow, loads the `.md` file for the selected meeting, and calls `AnswerAgent` with that content.
**Depends on:** Plan 07-01 (provides `MeetingIndexEntry`, `MeetingWriterAgent.read_index`, `MeetingWriterAgent.read_md`)

---

## Context

The current memory query path in `jarvis.py` routes through `OrchestratorAgent` → `RetrieverAgent` → Pinecone. Phase 7 adds a parallel path where the History Manager reads the JSON meeting index produced by Plan 07-01, picks the best meeting, reads its `.md` file, and passes the full content to `AnswerAgent` for answer synthesis. The History Manager does NOT replace the OrchestratorAgent — it is invoked instead of it when a `memory_query` is classified and the meeting index is available.

The disambiguation pattern mirrors the existing `OrchestratorAgent` disambiguation path at lines 224–247 of `agents/orchestrator.py` — same `OrchestratorResult` with `needs_disambiguation=True` and `disambiguation_options` list. The wiring of the History Manager into `handle_query()` is done in Plan 07-03.

Canonical references:
- `agents/orchestrator.py` — disambiguation pattern (lines 224–247) and `OrchestratorResult` model to reuse
- `agents/answer_agent.py` — `AnswerAgent.run()` signature; called with `.md` content as the context block
- `storage/models.py` — `MeetingIndexEntry` from Plan 07-01
- `agents/meeting_writer.py` — `MeetingWriterAgent.read_index()` and `read_md()`

## Tasks

### Task 1: Create `HistoryManagerAgent` in `agents/history_manager.py`

**File:** `agents/history_manager.py` (new file)
**Action:** Create
**Details:**
- `HistoryManagerAgent` is a plain Python class (NOT an `openai-agents Agent()` instance) — consistent with `OrchestratorAgent` and `RetrieverAgent` pattern.
- Constructor: `__init__(self, meeting_writer: MeetingWriterAgent, answer_agent: AnswerAgent, model: str = "gpt-4o-mini")`:
  - Stores `self._writer = meeting_writer`, `self._answer = answer_agent`, `self._model = model`
  - Creates `self._openai = AsyncOpenAI()`
- Module-level `_SELECTION_PROMPT` string:
  ```
  You are a meeting index selector. The user asked a question about a past meeting.
  You are given a JSON list of meeting index entries. Each entry has:
    meeting_id, title, date (YYYY-MM-DD), channel_name, overview, participants.

  Your task: identify which meeting(s) best match the user's question.

  Rules:
  - If exactly one meeting clearly matches → return its meeting_id in the "selected" field.
  - If two or more meetings are equally plausible → return all their meeting_ids in "candidates".
  - If no meeting is relevant → return an empty "selected" and empty "candidates".
  - Natural language date references ("last Thursday", "Q1 planning") should be resolved against the entry dates.
  - Do not make up meetings. Only reference entries in the provided list.

  Respond with JSON only:
  {"selected": "<meeting_id or empty string>", "candidates": ["<id>", ...]}
  ```
- Async method `_select_meeting(self, query: str, entries: list[MeetingIndexEntry]) -> dict`:
  - Serializes `entries` to a JSON array string: `json.dumps([e.model_dump() for e in entries])`
  - Calls `self._openai.chat.completions.create(model=self._model, messages=[{"role": "system", "content": _SELECTION_PROMPT}, {"role": "user", "content": f"Question: {query}\n\nMeeting index:\n{index_json}"}], max_tokens=200, temperature=0, response_format={"type": "json_object"})`
  - Parses response JSON; returns dict with keys `selected` (str) and `candidates` (list[str])
  - On any parse error, returns `{"selected": "", "candidates": []}` — safe no-op fallback
- Async method `run(self, query: str, user_id: str, channel_id: str) -> OrchestratorResult`:
  - Imports `OrchestratorResult` from `agents.orchestrator`
  - Calls `entries = await self._writer.read_index()`
  - If `entries` is empty: returns `OrchestratorResult(query=query, query_type="memory_query", answer="No meeting history found. No meetings have been recorded yet.", source_meeting_ids=[], confidence="low")`
  - Calls `selection = await self._select_meeting(query, entries)`
  - **Single match** (`selection["selected"]` is non-empty):
    - Finds `entry = next(e for e in entries if e.meeting_id == selection["selected"], None)`
    - If `entry` is `None` (LLM hallucinated an ID): returns not-found `OrchestratorResult` with `confidence="low"`
    - Calls `md_content = await self._writer.read_md(entry.md_path)`
    - Builds `context_block = f"Meeting: {entry.title} ({entry.date}, #{entry.channel_name})\n\n{md_content}"`
    - Calls `AnswerAgent.run()` BUT note: `AnswerAgent.run()` expects a `RetrievalResult`. To avoid coupling, pass context as a synthetic single-item `RetrievalResult` — create a helper `_md_to_retrieval_result(entry, md_content) -> RetrievalResult` that wraps it:
      ```python
      RetrievalResult(
          query=query,
          results=[{"id": entry.meeting_id, "score": 1.0, "metadata": {"channel_name": entry.channel_name, "start_ts": entry.start_ts, "summary_text": md_content, "decisions": [], "topics_covered": [], "participants": entry.participants, "action_items": []}}],
          total_candidates=1,
          returned_count=1,
      )
      ```
      All four Pydantic-required fields must be populated — omitting any will raise `ValidationError` at runtime.
    - Calls `answer_out = await self._answer.run(query=query, retrieval_result=rr, query_type="memory_query")`
    - Returns `OrchestratorResult(query=query, query_type="memory_query", answer=answer_out.answer, source_meeting_ids=[entry.meeting_id], confidence=answer_out.confidence)`
  - **Multiple candidates** (`selection["candidates"]` has 2+ items):
    - Filters `entries` to only those whose `meeting_id` is in `selection["candidates"]`
    - Builds `disambiguation_options` list (per D-08), reusing the same format as `OrchestratorAgent` (lines 226–238 of `agents/orchestrator.py`):
      ```python
      [{"index": i+1, "meeting_id": e.meeting_id, "title": e.title, "channel": e.channel_name, "date": e.date} for i, e in enumerate(candidate_entries)]
      ```
    - Returns `OrchestratorResult(query=query, query_type="memory_query", answer="Multiple meetings matched. Please select one:", source_meeting_ids=[e.meeting_id for e in candidate_entries], confidence="low", needs_disambiguation=True, disambiguation_options=options)`
  - **No match** (both `selected` empty and `candidates` empty):
    - Returns `OrchestratorResult(..., answer="I couldn't find a relevant meeting in the history. Try Pinecone search with /ask.", source_meeting_ids=[], confidence="low")`

### Task 2: Pinecone semantic fallback integration in `HistoryManagerAgent`

**File:** `agents/history_manager.py`
**Action:** Extend Task 1's `run()` method with fallback logic (per D-09)
**Details:**
- Add optional constructor parameter: `retriever: Optional[RetrieverAgent] = None` — stored as `self._retriever`
- In `run()`, when the LLM selection returns no match AND `self._retriever` is not `None`:
  - Log: `logger.info("HistoryManager: no index match, falling back to Pinecone retrieval")`
  - Calls `retrieval_result = await self._retriever.retrieve(query_text=query, channel_id=channel_id or None)`
  - If `retrieval_result.results` is non-empty:
    - Calls `answer_out = await self._answer.run(query=query, retrieval_result=retrieval_result, query_type="memory_query")`
    - Returns `OrchestratorResult(..., answer=answer_out.answer, source_meeting_ids=answer_out.source_meeting_ids, confidence=answer_out.confidence)`
  - If still no results: return the "no match" result from Task 1
- Import `RetrieverAgent` from `agents.retriever` inside the method body (or at module top behind `TYPE_CHECKING`) to avoid circular import.

## Success Criteria

1. `agents/history_manager.py` exports `HistoryManagerAgent` with an async `run(query, user_id, channel_id) -> OrchestratorResult` method.
2. When exactly one meeting matches: the `.md` file is read, passed to `AnswerAgent`, and the result is returned as an `OrchestratorResult` with `needs_disambiguation=False`.
3. When multiple meetings match: `OrchestratorResult` is returned with `needs_disambiguation=True` and `disambiguation_options` formatted identically to the Phase 5 pattern in `agents/orchestrator.py`.
4. When no meeting matches and `retriever` is set: Pinecone fallback is invoked via `RetrieverAgent.retrieve()`.
5. When no meeting matches and `retriever` is None: a graceful "no match" `OrchestratorResult` is returned without raising.
6. JSON parse errors in `_select_meeting` are swallowed; `{"selected": "", "candidates": []}` is returned.
7. `pytest tests/test_history_manager.py -v` passes with 6 tests, no failures.
8. `HistoryManagerAgent` does not import from `jarvis.py` (no circular dependency).
