# Plan 07-01: Rolling Summarizer + Meeting Writer

**Phase:** 7 — Fully Agentic Meeting Pipeline Redesign
**Goal:** Introduce a sentence buffer with dual-trigger flushing (N sentences OR T minutes), a `BatchSummaryOutput` Pydantic schema, a `MeetingWriterAgent` that appends structured `.md` sections to a per-meeting file, and a JSON meeting index maintained alongside those files.
**Depends on:** Nothing (first plan in phase)

---

## Context

The existing `SummarizerAgent` runs once at end-of-meeting. This plan does NOT remove that agent — it adds new infrastructure alongside it. The sentence buffer accumulates transcript sentences in `jarvis.py`'s WebSocket handler. When a flush threshold is crossed the buffer is handed to a new `RollingSummarizerAgent` which returns a `BatchSummaryOutput`. A `MeetingWriterAgent` then appends a formatted section to a per-meeting `.md` file and updates a JSON index used by the History Manager (Plan 07-02).

Key wiring in `jarvis.py` is deferred to Plan 07-03. This plan only creates the new agent classes and the data models they depend on.

Canonical references:
- `agents/summarizer.py` — pattern for `Agent(output_type=...)` and `Runner.run()`
- `storage/metadata_store.py` — async file I/O with `aiofiles`; locking pattern to follow
- `storage/models.py` — existing `MeetingRecord` Pydantic model; new index entry must be compatible
- `jarvis.py` `_split_sentences()` — sentence-counting utility (Phase 6); reuse here

## Tasks

### Task 1: Define `BatchSummaryOutput` and `MeetingIndexEntry` Pydantic models

**File:** `storage/models.py`
**Action:** Extend (append — do not modify existing classes)
**Details:**
- Add `BatchSummaryOutput(BaseModel)` with fields:
  - `summary_text: str` — 2–4 sentence prose summary of this batch
  - `key_points: list[str]` — bullet-point key points from this batch (short phrases)
  - `speakers: list[str]` — speaker names active in this batch (extracted from transcript lines)
- Add `MeetingIndexEntry(BaseModel)` with fields:
  - `meeting_id: str`
  - `title: str` — derived from channel name or meeting metadata
  - `date: str` — ISO date string (YYYY-MM-DD)
  - `channel_id: str`
  - `channel_name: str`
  - `overview: str` — 1–2 sentence description of the meeting so far (updated each batch)
  - `md_path: str` — relative path to the `.md` file (e.g. `meetings/C123/2026-04-05_mtg-abc.md`)
  - `participants: list[str]` — accumulated unique participant names across all batches so far
  - `start_ts: int` — Unix epoch integer (same constraint as `MeetingRecord.start_ts`)
- Both models follow the existing pattern: all flat fields, no nested objects, Unix timestamps as `int`.

### Task 2: Create `RollingSummarizerAgent` in `agents/rolling_summarizer.py`

**File:** `agents/rolling_summarizer.py` (new file)
**Action:** Create
**Details:**
- Class `RollingSummarizerAgent` following the same `Agent(output_type=...)` pattern as `SummarizerAgent` in `agents/summarizer.py`.
- Constructor: `__init__(self, model: str = "gpt-4o-mini")` — stores `self._model`; creates `self._agent = Agent(name="rolling-batch-summarizer", instructions=_INSTRUCTIONS, model=model, output_type=BatchSummaryOutput)`.
- `_INSTRUCTIONS` system prompt (module-level string):
  ```
  You are a real-time meeting summarizer. Given a batch of meeting transcript lines
  (format: "Speaker: utterance"), produce a concise summary of this batch only.

  Return:
  - summary_text: 2-4 sentence prose. Be specific — name topics and outcomes discussed.
  - key_points: Up to 5 short bullet-point phrases capturing the most important points.
  - speakers: List of unique speaker names who appear in the transcript lines.

  Stay factual. Do not infer beyond what is said. Do not reference other batches.
  ```
- Async method `run(self, batch_transcript: str) -> BatchSummaryOutput`:
  - `batch_transcript` is a string of transcript lines: `"Speaker: text\nSpeaker2: text\n..."`
  - Calls `result = await Runner.run(self._agent, input=batch_transcript)`
  - Returns `result.final_output` (a `BatchSummaryOutput` instance)
  - Does NOT catch exceptions — callers handle failures.

### Task 3: Create `MeetingWriterAgent` in `agents/meeting_writer.py`

**File:** `agents/meeting_writer.py` (new file)
**Action:** Create
**Details:**
- This is a plain Python class (NOT an `openai-agents Agent()` instance) — pure I/O, no LLM calls.
- Constructor: `__init__(self, base_dir: str = "./meetings")`:
  - Stores `self._base_dir = Path(base_dir)`
  - Creates `self._lock = asyncio.Lock()` — all file writes protected (per Phase 1 mandate)
  - Creates `self._index_path = Path(base_dir) / "meeting_index.json"` — single JSON array file
- Method `_md_path(self, channel_id: str, date_str: str, meeting_id: str) -> Path`:
  - Returns `self._base_dir / channel_id / f"{date_str}_{meeting_id}.md"` (per discretion decision)
- Async method `write_meeting_header(self, entry: MeetingIndexEntry) -> None`:
  - Acquires `self._lock`
  - Creates directory with `mkdir(parents=True, exist_ok=True)`
  - Opens `.md` file at `_md_path(entry.channel_id, entry.date, entry.meeting_id)` in write mode (`"w"`) using `aiofiles`
  - Writes header block (per D-05):
    ```markdown
    # Meeting: {entry.title}

    **Date:** {entry.date}
    **Channel:** {entry.channel_name}
    **Participants:** {", ".join(entry.participants) or "TBD"}
    **Meeting ID:** {entry.meeting_id}

    ---

    ```
  - Does NOT write any batch sections yet — those are appended by `append_batch`.
- Async method `append_batch(self, entry: MeetingIndexEntry, batch_num: int, batch_summary: BatchSummaryOutput, timestamp_str: str) -> None`:
  - `timestamp_str` is formatted by caller as `"HH:MM AM/PM"` (e.g. `"10:32 AM"`)
  - Acquires `self._lock`
  - Opens `.md` file in append mode (`"a"`) using `aiofiles`
  - Writes section (per D-03, D-04, D-06):
    ```markdown
    ## {timestamp_str} — Batch {batch_num}

    {batch_summary.summary_text}

    **Key Points:**
    {chr(10).join(f"- {p}" for p in batch_summary.key_points)}

    **Speakers:** {", ".join(batch_summary.speakers)}

    ---

    ```
  - Existing content is never rewritten — append-only ensures concurrent read safety (D-06).
- Async method `upsert_index(self, entry: MeetingIndexEntry) -> None`:
  - Acquires `self._lock`
  - Reads `self._index_path` if it exists, else starts with `[]`; parses as JSON list
  - Finds existing entry by `meeting_id`; replaces it if found, appends if not
  - Writes updated list back to `self._index_path` using `aiofiles` in write mode
  - Serializes using `entry.model_dump_json()` — store each entry as a dict in the JSON array
  - Index file format: `[{...MeetingIndexEntry fields...}, ...]`
- Async method `read_index(self) -> list[MeetingIndexEntry]`:
  - Acquires `self._lock`
  - Returns `[]` if `self._index_path` does not exist
  - Reads and parses JSON; returns list of `MeetingIndexEntry` objects via `MeetingIndexEntry.model_validate(item)` for each dict
- Async method `read_md(self, md_path: str) -> str`:
  - No lock needed (read-only, append-only target)
  - Opens `Path(md_path)`, reads and returns full string content
  - Raises `FileNotFoundError` if not found (matches `MetadataStore` pattern)
